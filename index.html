ShiftLefter

A type checker for your test suite.

Compile errors for end-to-end tests.

An end-to-end test framework that compiles plain-language scenarios against a vocabulary you declare.

Your end-to-end suite fails with a selector timeout, and nobody can tell an app bug from a test bug from a down environment. A green on a down environment is a lie. Steps are regular expressions over strings, so nothing is checked until a browser is open. And the tests your coding agent wrote are one-offs nobody will maintain.

BDD was right that plain-language scenarios are the contract between people and the machine, and wrong that regexes and hand-written glue could hold it up. Agents remove the glue cost. A typed vocabulary removes the rot.

Agents write the tests. The vocabulary is yours. The compiler is the referee.

We don’t heal your tests. We name what changed.

Built by one engineer with agents in the loop — why I built this.

Three proofs

Nothing on this site is mocked: every box is output captured from a real run, kept under assets/homepage with the commit and command that produced it. The tour has the long version of each.

Compile errors, before a browser opens

:user/alice is a declared subject and an instance — a keyword naming the subject’s type and the instance, declared in the glossary. Misspell the actor, or name an element the glossary never declared, and the run refuses to start:

A typo is the fastest case to see. The real ones: a glossary entry renamed and dangling across forty scenarios, a merge that leaves references pointing nowhere, a refactored step library. Each dies before a browser opens, with a suggestion and the file and line where the right name is declared. The refusal, in full →

A green is a measurement

A run that could not observe the app says so in its exit code, never in a green. Here the port had nothing listening:

Exits 0 and 1 are verdicts about your app. Exit 4 means no answer existed, and it is never blamed on the app. The exit-code contract →
