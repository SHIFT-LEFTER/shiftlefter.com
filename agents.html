For agents

Install, then ask the tool itself

If you are an agent, or you brought one: the documentation is in the jar. Nothing on this page needs the repository, a wiki, or a search. Every box is captured output.

Three commands

curl -fsSL https://raw.githubusercontent.com/SHIFT-LEFTER/shiftlefter/main/release/install.sh | bash
./sl/sl orient            # where am I, what would fail, what to read next
./sl/sl agent-doc --list

Java 21+ is the only requirement. The installer prints a breadcrumb stanza to paste into your AGENTS.md, so the next agent in the project finds the same three commands.

The built-in verbs, their frames and their step patterns are generated from the registered steps (sl agent-doc builtins), so the reference cannot drift from the code. sl glossary and sl explain answer what a word means in this project and who uses it.

Hand it a suite it has never seen

Point it at a Cucumber suite nobody has typed. It parses everything, runs nothing, says what it saw, and names the next command:

Unshifted means untyped; shifted means typed. The compiler runs only typed steps, by choice, so an existing step library does not run here; feature files and page objects migrate, and sl agent-doc adoption says how. The tests an agent writes against this surface are a feature file and a glossary — durable project artifacts the next person can read — not a generated script.

Pointers

  • docs/AGENT.md — the agent-facing manual, on GitHub; the same text the jar serves.
  • /llms.txt — a plain-text pointer to this site and the repository.
  • The tour — every feature with its captured in and out, for the human you brought along.

Next release: a skill and a tone prompt — hand your agent the on-ramp, not a URL. For the record: without a skill, a fresh agent given this framework and a FastAPI service authored an HTTP interface for it — five scenarios dry-run green on the first attempt, and the first live run green (August 2026). The skill turns that into a recipe.
