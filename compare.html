Compared

What the others do, and what this does

One row per claim. The left column is the named tool on its own terms, from its own documentation; the right is ShiftLefter. Where the other tool is simply better at something, the row says so.

OnThe named toolShiftLefter
What a step is Cucumber. A step definition is a method with an expression — a regular expression or a Cucumber Expression — that links it to one or more Gherkin steps. The text is matched; capture groups become the method’s arguments. Whatever matches, runs. A step is a sentence: a subject, a verb and an object, each resolved against a glossary you own. The glue is the vocabulary, not a method per phrase. The refusal
When a mistake is found Cucumber reports an undefined step when the suite runs, with a snippet to implement it. Playwright locates an element “every time a locator is used for an action”; a wrong locator is a timeout, at run time, with the browser open. Before the run. A misspelled actor, a misspelled element, a dangling rename: each stops the run with a suggestion and the file and line where the right name is declared. Exit 2; no browser opened. The refusal
Page objects Playwright recommends a helper class per page, locators as fields, methods for the actions. Screenplay (Serenity) puts targets and tasks in classes too. A page object is a data file: an intent with the elements and collections it owns. Addressed by path — Cart.items[-1].remove — with indexes, negative indexes, and [*] for all members. No code. Page objects as data
Reusing a workflow Screenplay composes Tasks from Interactions in code; Tasks are “reusable building blocks from which your team can assemble test scenarios.” It is a good pattern, and it is a class hierarchy. A macro: a named step sequence written in Gherkin, expanded before binding, with provenance kept in the report. The reuse Screenplay reaches for, without the classes. Macros
Several actors Screenplay (Serenity BDD) has actors as first-class objects, and with a cast “each actor can have their own browser.” Set up in code. Playwright gives you browser contexts to isolate sessions, also in code. Declare :user with instances alice and bob in a two-line glossary; write :user/alice and :user/bob in one scenario; each gets its own browser. No setup. Nothing in the harness says what alice may do; the scenarios do, and substituting the actor is how you find out. Two actors
On failure Playwright’s trace viewer records a screencast, a DOM snapshot before and after each action, the console and the network — richer per action than anything here. Cucumber gives you the step’s exception and stack trace. The row: which actor, which intent, which step; expected against seen, with the poll count; the screenshot and the console attached at the instant of failure — in your vocabulary, and the same in HTML, JUnit XML and the machine-readable record. The failure row
A down environment Playwright and Cucumber report a failed navigation as a failed test: the same red as a wrong assertion, and the same exit status. Exit 4, unobserved: the run could not measure, so it says so in its exit code and never issues a verdict about the app. Exits 0 and 1 are verdicts; 2, 3 and 4 are three ways the run failed to be a measurement. The exit-code contract
When the page changes Self-healing tools (Healenium, for one) work “by automatically detecting and healing test failures caused by changes in the UI”: a locator that stops matching is replaced and the run goes on. We don’t heal your tests. We name what changed. An agent working with ShiftLefter gets the same named delta and may heal it itself, as an explicit edit to one binding that the record shows — never a silent substitution at run time. The locator lives in one intent file, so the fix is one binding and zero scenarios — and a reference that no longer resolves is a refusal, not a guess.
For agents Playwright MCP lets an agent drive a live browser through the accessibility tree — a strong way to explore an app. What it leaves behind is a session. The agent reads the vocabulary and the documentation inside the jar (sl orient, sl agent-doc) and writes scenarios that compile. The live door is the REPL: sl repl, for humans and agents alike, runs steps against a live browser. What it leaves behind is a feature file and a glossary the next person can read. For agents
Gherkin compatibility Cucumber is the reference implementation of Gherkin, and its step libraries are written against Cucumber’s API. The parser accepts every legal Gherkin file (50 of 50 official files; 12 of 12 invalid ones rejected). The compiler runs only typed steps, by choice. An existing step library does not run here; feature files and page objects migrate. The parser
